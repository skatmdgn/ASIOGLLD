# Phase 1: 원본 그대로 복원 (최상위 원칙)

**사용자 지시: 기존 asioglld.dll을 먼저 가능한 한 완전하게 역공학하고 기능과 동작을 그대로 재현한 다음에만 최적화한다.**
현재 Phase 1에서는 최적화, 새 API로의 대체, 편의상 기능 생략, 재설계를 금지한다.

## 복원 범위
- DLL/PE 구조, 내보내기, COM 객체 수명, 클래스 레이아웃, 모든 식별 가능한 함수와 제어 흐름.
- ASIO 인터페이스 전체, 더블버퍼, 콜백 타이밍, 데이터 변환, 샘플 위치, 반환 코드.
- WASAPI 공유 **및 독점** 모드, 녹음 **및 재생**, 모든 지원 포맷, 버퍼와 이벤트 처리.
- 장치 열거 및 변경, 설정과 UI, 레지스트리, 스레드/동기화, 실패/종료 처리.
- Cubase 8.0.40과 유튜브 동시 재생은 중요한 원본 동작 검증 케이스. 그 외 원본 기능도 생략하지 않는다.

## 엄격한 검증 원칙
- BYTE_CONFIRMED: 실제 원본 바이트, RTTI, 기계어 확인.
- STATIC_INFERRED: 정적 분석에서 논리적으로 추정.
- DYNAMIC_CONFIRMED: 원본을 실행해 API/상태/분기 확인.
- REFERENCE_ONLY: ASIO SDK, FlexASIO 등 외부 참고 사례.
- UNRESOLVED: 미확인 구조·알고리즘·분기.
- PARITY_VERIFIED: 원본과 재현 구현을 동일 조건에서 직접 비교 통과.

모든 함수에 원본 RVA, 코드/분기 분석, 근거, 재구현 대응 위치 및 불확실성을 기록한다. 누락/미확인 영역이 있으면 '완벽히 복원했다'고 말하지 않는다.

## 복원과 원본 C++ 동일성은 다름
컴파일된 바이너리에서 원래 주석, 로컬 변수명, 소스 파일 구성, 최적화 전의 문장 표현까지 항상 복구할 수는 없다. 따라서 **원본 C++ 텍스트를 100% 복원한다고 보장하지 않는다.** 실제 목표는 내부 처리와 기능을 최대한 빠짐없이 이해하고, 비교 가능한 환경에서 원본과 기능/동작이 동등한 독립 재현 구현을 만드는 것이다.

## 금지 사항
1. Phase 1에서 성능 개선, 코드 축약, 스레딩/버퍼/알고리즘 교체를 하지 않는다.
2. FlexASIO의 방식을 원본의 실제 동작인 것처럼 대체하지 않는다.
3. 일부만 구현한 출력 전용/공유 모드 전용 드라이버를 원본 완전 복원으로 부르지 않는다.
4. 원본 시스템 DLL을 덮어쓰지 않고, 공개 저장소에 원본 DLL이나 대량의 proprietary 의사코드를 올리지 않는다.
5. '정적 분석 완료'와 '원본 동작 동일성 검증 완료'를 혼동하지 않는다.

## 게이트
G0 원본 식별 및 보존 → G1 정적 전수 인벤토리 → G2 모든 동작 경로 명세 → G3 원본 Windows 동적 검증 → G4 기능 보존 재구현 → G5 원본과 재현 구현의 동일 조건 차등 테스트.

**G1~G5 검토가 끝나고 사용자의 별도 동의를 받기 전까지 Phase 2(최적화)에 진입하지 않는다.**
